# تقرير فحص الأداء (الأسئلة 1–15)

1. **زمن الاستجابة للمسارات /api/home, /api/items, /api/search, /api/cart/summary, /api/delivery-prices/calculate (P50/P95).**
    - لا يوجد نظام قياس زمني داخل التطبيق؛ خدمة القياس المتاحة (`TelemetryService`) تكتفي بتسجيل الأحداث في السجلات بدون تجميع إحصائيات زمنية. بالتالي لا يمكن استخراج قيم P50/P95 من المستودع الحالي.【F:app/Services/TelemetryService.php†L1-L19】

2. **سياسة Pagination (افتراضي 10–20، وحد أقصى ≤50).**
    - بعض القوائم (مثل الإشعارات) تفرض حدًا أقصى 50 عنصراً مع افتراضي 20، وهو متوافق مع السياسة المطلوبة.【F:app/Http/Controllers/ApiController.php†L2134-L2154】
    - في المقابل هناك قوائم أخرى تسمح حتى 100 عنصر في الصفحة (مثل معاملات المحفظة)، ما يعني أن السياسة ليست موحدة بعد.【F:app/Http/Controllers/ApiController.php†L2805-L2839】

3. **حجم JSON P95 للقوائم (≤100KB).**
    - لا توجد أدوات مراقبة أو قياسات للحجم ضمن المستودع، لذا لا يمكن تقديم قيم فعلية لحجم JSON أو التأكد من الالتزام بالحد الأقصى.【F:app/Services/TelemetryService.php†L1-L19】

4. **تفعيل ضغط Gzip/Brotli لكل JSON.**
    - إعدادات التخديم في `.htaccess` تقتصر على إعادة الكتابة والتوجيه إلى `index.php`، ولا يوجد أي تفعيل للضغط داخل المشروع. يفترض ضبطه على خادم الويب الخارجي، لكنه غير موثق هنا.【F:public/.htaccess†L1-L24】

5. **تنسيقات الصور (WebP/AVIF) وإنشاء Thumbnails.**
    - خدمة رفع الملفات تتعامل مع ‎JPG/PNG فقط، وتعيد رفع باقي الامتدادات كما هي بدون تحويل إلى WebP/AVIF أو إنشاء نسخ مصغرة قياسية، كما لا توجد حقول تُعبّأ بمشتقات الصور داخل التطبيق.【F:app/Services/FileService.php†L12-L120】

6. **CDN / Static + Cache-Control + ETag، ومدة TTL للصور وJSON.**
    - التخزين الافتراضي موجه إلى قرص `public` المحلي مع رابط `APP_URL/storage`، ولا يوجد تكامل مُعدّ مع CDN أو إعدادات صريحة لـ Cache-Control/ETag داخل المشروع.【F:config/filesystems.php†L16-L74】【F:public/.htaccess†L1-L24】

7. **تفعيل Redis cache لمسارات القوائم/الرئيسية (hit rate وTTL).**
    - إعداد التخزين المؤقت الافتراضي هو `file`، ولم يتم رصد اعتماد صريح على Redis أو إحصائيات للـ hit rate/TTL في الشيفرة الحالية.【F:config/cache.php†L6-L80】

8. **تفعيل slow query log وأعلى 5 استعلامات بطيئة.**
    - إعداد قاعدة البيانات يستخدم إعدادات MySQL الافتراضية بدون أي مفاتيح لتفعيل slow query log أو جمع تقارير الاستعلامات البطيئة، لذلك لا تتوفر البيانات المطلوبة.【F:config/database.php†L19-L38】

9. **إضافة فهارس على الحقول category_id,status,price,created_at,vendor_id,popularity.**
    - جداول العناصر تُنشأ بدون أي فهارس إضافية على هذه الأعمدة، ما يعني أن الاستعلامات ستعتمد على الفهارس الافتراضية فقط.【F:database/migrations/2024_02_20_051429_v1.0.0.php†L38-L66】

10. **معالجة مشكلة N+1 عبر eager loading (مع مثال بالأرقام).**
    - بالرغم من توفر حزمة تطويرية لكشف N+1، لا توجد أمثلة أو قياسات في المستودع تثبت إزالة المشكلة أو توثيق أرقام الأداء المطلوبة، لذا لا يمكن تأكيد الحل.【F:composer.json†L46-L57】

11. **زمن /api/delivery-prices/calculate (P50/P95) وسياسة التخزين المؤقت 30–120 ثانية.**
    - المسار معرّف في `routes/api.php` ليعيد استجابة ثابتة (`{"ok": true}`) بدون استدعاء خدمة أو كاش، ولا توجد قياسات زمنية أو تخزين مؤقت للطلبات المتطابقة.【F:routes/api.php†L26-L32】

12. **عزل الطلبات الثقيلة في Queue وعدد العمال.**
    - نظام الطوابير مضبوط افتراضيًا على `sync`، ما يعني تنفيذ المهام فورًا في نفس الطلب؛ لا يوجد إعداد لعدد العمال أو تشغيل فعلي لخلفيات مستقلة داخل المستودع.【F:config/queue.php†L16-L52】

13. **تفعيل HTTP/2 و keep-alive.**
    - إعدادات الخادم (Nginx/Apache) غير موجودة في المستودع؛ `.htaccess` لا يذكر أي ضبط لـ HTTP/2 أو keep-alive، لذلك لا يمكن تأكيد الحالة من الشيفرة الحالية.【F:public/.htaccess†L1-L24】

14. **إعدادات الأداء للتطبيق (OPcache، memory_limit، opcache.memory_consumption، PHP-FPM pm.max_children).**
    - لا توجد ملفات إعداد خادم PHP ضمن المستودع (php.ini أو fpm.conf) توضح هذه القيم، وبالتالي لا تتوفر معلومات عن التكوين الفعلي.【F:composer.json†L95-L104】

15. **قاعدة البيانات: حجم InnoDB buffer pool، البيانات الساخنة، ونسبة read hits.**
    - إعدادات MySQL في المشروع لا تتضمن أي ضبط خاص بالـ buffer pool أو مؤشرات الأداء، ولم يتم تضمين أي تقارير استعمال يمكن الرجوع إليها.【F:config/database.php†L19-L38】
